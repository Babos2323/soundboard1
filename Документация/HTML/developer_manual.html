Руководство разработчика

Стек технологий

  • Python 3.10+ (проверено на 3.12);

  • PyQt6 — интерфейс, сигналы и слоты;

  • pygame.mixer — воспроизведение и миксирование звука;

  • pynput — глобальные горячие клавиши;

  • JSON — хранение библиотеки и настроек;

  • PyInstaller — сборка Windows-приложения;

  • Sphinx + sphinx-rtd-theme — документация;

  • Git — контроль версий.

Структура проекта

soundboard/
├── .venv/                  # виртуальное окружение Python
├── Код/                    # исходный код приложения
│   ├── main.py             # точка входа
│   ├── main_window.py      # интерфейс и контроллер
│   ├── audio_engine.py     # аудиодвижок
│   ├── sound_manager.py    # библиотека звуков
│   ├── config_repository.py# JSON-хранилище
│   ├── models.py           # модель Sound
│   ├── dialogs.py          # диалоги
│   ├── hotkey_manager.py   # глобальные клавиши
│   ├── keys.py             # приведение клавиш
│   ├── theme.py            # тёмная тема
│   ├── assets/             # иконка приложения
│   ├── tests/              # модульные тесты
│   ├── dist/Soundboard/    # готовая Windows-сборка
│   ├── build_exe.bat       # сборка exe
│   ├── README.md           # краткое описание и запуск
│   └── BACKLOG.md          # бэклог продукта
└── Документация/
    ├── HTML/               # собранная Sphinx-документация
    ├── Sphinx/             # исходники документации
    ├── Презентация/        # pptx и pdf для защиты
    └── Отчёт/              # отчёт с приложениями

Настройка окружения (Windows)

cd C:\Users\<user>\Desktop\soundboard
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r Код\requirements.txt

Запуск из исходного кода:

.\.venv\Scripts\python.exe Код\main.py

Сборка Windows-приложения

Скрипт Код\build_exe.bat создаёт папку Код\dist\Soundboard с Soundboard.exe и _internal. Используется режим onedir: приложение не распаковывается во временную папку при каждом запуске и работает стабильнее onefile (у onefile возможна ошибка «Could not create temporary directory» при ограничениях TEMP или антивируса).

Ручная команда (из папки Код):

..\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean ^
  --noconsole --onedir --name Soundboard --icon assets\icon.ico ^
  --add-data "assets\icon.png;assets" ^
  --hidden-import pynput.keyboard._win32 ^
  --hidden-import pynput.mouse._win32 main.py

Готовую папку dist\Soundboard можно копировать на другой компьютер: Python и библиотеки на целевой машине не нужны.

Тесты

В проекте используются стандартные модульные тесты (unittest), не требующие дополнительных зависимостей:

cd Код
..\.venv\Scripts\python.exe -m unittest discover -s tests -v

Тесты проверяют сериализацию модели, сохранение/загрузку конфигурации, операции библиотеки, разбор клавиш и аудиодвижок на dummy-драйвере SDL. Для аудиотестов устанавливается SDL_AUDIODRIVER=dummy.

Документация Sphinx

Исходники находятся в Документация\Sphinx, собранный HTML — в Документация\HTML. Сборка:

cd Документация\Sphinx
..\..\.venv\Scripts\python.exe -m pip install -r requirements.txt
..\..\.venv\Scripts\python.exe -m sphinx -b html . ..\HTML

Или двойным кликом по build_docs.bat. Готовый файл — Документация\HTML\index.html.

  • conf.py добавляет каталог Код в sys.path и включает sphinx.ext.autodoc, sphinx.ext.napoleon, viewcode;

  • API-страницы строятся автоматически из docstrings модулей (Google style);

  • архитектура, функциональность, руководства и примеры — обычные RST-страницы;

  • при добавлении нового модуля достаточно добавить automodule в api.rst и краткое описание в architecture.rst.

Требования к коду

  • PEP 8, отступы 4 пробела, длина строки — до 100 символов;

  • у модулей, классов и публичных методов — docstrings;

  • стиль docstrings — Google (Args/Returns/Raises), поддерживается расширением sphinx.ext.napoleon;

  • интерфейс не работает с pygame напрямую — только через AudioEngine;

  • изменения модели сохраняются через ConfigRepository;

  • новые сигналы и слоты документируются и связываются в MainWindow.

Архитектурные правила

  • View (SoundsPage, SoundCard) не хранит бизнес-состояние;

  • Controller (MainWindow) — единственное место связи UI и движка;

  • Model (SoundManager) не импортирует PyQt6-виджеты;

  • AudioEngine не знает о библиотеке и интерфейсе;

  • ConfigRepository отвечает только за JSON;

  • громкость, перемотка и цикл применяются к движку, а модель обновляется без пересборки карточек (silent=True), чтобы не сбрасывать прокрутку.

Как добавить новую функцию

  1. Определите, к какому слою относится изменение (модель, движок, UI).

  2. Добавьте поле в модель и миграцию конфигурации (значение по умолчанию).

  3. Реализуйте логику в соответствующем модуле и покройте тестом.

  4. Добавьте элемент управления в интерфейс и свяжите сигнал в MainWindow.

  5. Обновите документацию (functionality.rst, api.rst, при необходимости руководства) и BACKLOG.md.

  6. Проверьте сборку exe и запуск на чистой конфигурации.

Релизный чек-лист

  • [ ] все тесты проходят (python -m unittest discover -s tests);

  • [ ] документация собирается без ошибок и предупреждений;

  • [ ] обновлены BACKLOG.md и changelog.rst;

  • [ ] собрана Windows-папка dist\Soundboard;

  • [ ] проверен запуск с чистой конфигурацией;

  • [ ] обновлены отчёт и презентация, если менялись функции.

Передача знаний новому разработчику

  1. Прочитайте README.md и эту страницу — они дают полную картину.

  2. Запустите приложение и пройдите сценарий из user_manual.rst.

  3. Посмотрите architecture.rst и api.rst — там границы слоёв.

  4. Соберите документацию и тесты — это быстрый способ проверить окружение.

  5. Начните с задач из BACKLOG.md с меткой «good first issue».

  6. Ключевые точки кода: MainWindow (связи), AudioEngine (звук), ConfigRepository (хранение), SoundsPage (сетка карточек).

Известные ограничения

  • используется аудиоустройство Windows по умолчанию;

  • перемотка длинных MP3 выполняется копированием PCM-фрагмента и может занимать десятки миллисекунд;

  • интерфейс только на русском языке;

  • Windows-сборка не подписана, антивирус может запросить подтверждение.

Актуальный список задач и багов — в BACKLOG.md и на странице Поддержка и развитие проекта.
