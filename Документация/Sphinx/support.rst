Поддержка и развитие проекта
============================

Процесс поддержки
-----------------

После релиза проект сопровождается по простому циклу:

#. **Сбор обратной связи** — ошибки и пожелания фиксируются в бэклоге.
#. **Приоритизация** — задачи делятся на критические, важные и минорные.
#. **Исправление и проверка** — изменения проходят тесты и ручные сценарии.
#. **Релиз** — обновляются версия, сборки и документация.

Отслеживание ошибок
-------------------

Для проекта подготовлены шаблоны GitHub Issues:

* ``.github/ISSUE_TEMPLATE/bug_report.md`` — описание ошибки;
* ``.github/ISSUE_TEMPLATE/feature_request.md`` — предложение функции;
* ``.github/ISSUE_TEMPLATE/config.yml`` — настройки выбора шаблона.

Рекомендуемый процесс:

#. Пользователь создаёт issue по шаблону (шаги, ожидаемое/фактическое поведение,
   версия ОС, версия приложения).
#. Ошибка воспроизводится, ей назначается приоритет и метка.
#. Исправление оформляется отдельной веткой и проверяется тестами.
#. После релиза issue закрывается со ссылкой на изменение.

Если GitHub недоступен, используется локальный ``BACKLOG.md``:
задача добавляется в таблицу с тем же набором полей.

Известные ограничения
---------------------

* используется аудиоустройство по умолчанию;
* перемотка очень длинных файлов может занимать десятки миллисекунд;
* интерфейс на русском языке;
* Windows-сборка не подписана — антивирус может запросить подтверждение.
